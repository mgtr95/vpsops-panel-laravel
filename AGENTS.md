# Agent instructions (VPSops)

When asked to install or recreate this stack on a VPS:

1. Follow [docs/NEW_VPS.md](docs/NEW_VPS.md) **exactly**. Do not invent a second Docker architecture.
2. Production Laravel+React apps use the **panel template only** (generated `Dockerfile.panel` + `docker-compose.panel.yml`). Ignore Docker files inside the Laravel repos for production.
3. TLS is **nginx + certbot** started from the panel (**Websites**). FrankenPHP in each app listens on **:80 only**. Do not put Caddy on ports 80/443 (`docker-compose.https.yml` is the wrong path on an app server).
4. Do not copy `config/apps.json`, `.env`, or Docker volumes from another VPS.

Before changing **container alerts**, Docker issue copy, log matching, the Laravel **queue worker** command, **Postgres healthcheck**, **backup jobs**, **database connections**, **template adopt**, **rclone remotes**, the Laravel **compose network layout** (proxy vs internal for DB/redis), or **per-app PHP upload limits** (`.panel/php` bind mount / nginx `client_max_body_size`), read [docs/AUDIT.md](docs/AUDIT.md). **Always** append a dated entry there when you change that area (not only when it was a dash bug). Do not reintroduce those fixes (hourly `*_queue` recycle mail, hashed `*-error-*.js` / `/.env-traceback` log hits, log-scan hashing the whole tail, scanning `vps_dashboard` logs, `pg_isready` without `-d $DB`, exit 137 as OOM, backup jobs left on an old discovered SQL hostname after adopt, OneDrive remotes saved with only an OAuth token and empty `drive_id`/`drive_type`, app-file backups wrapping dest as `destination/storage/app/...` or default-checking whole `storage/app`, Laravel `storage/` / uploads / SQLite `database/` in a named Docker volume after adopt, database/redis services on the shared proxy network where short names collide, PHP upload defaults left at 2M/8M after panel template). Do not remove `--max-time` from queue workers to silence alerts. After a template switch, scheduled SQL backups must follow `{slug}_postgres` / `{slug}_mysql` (`{slug}-db`), not the old discovered hostname. App-file backups sync **folder contents** into the chosen remote folder (e.g. `storage/app/public/attachments` files, not a nested `storage/app` tree). Live uploads must stay on the host bind mount (`./storage/app`), not `storage:/app/storage/app`. SQLite must stay on `./database`, not `database:/app/database`. Postgres/MySQL/redis must stay on the app **`internal`** network only (not `proxy`). Per-app PHP limits use `.panel/php/zz-panel.ini` bind-mounted into conf.d — do not drop that mount or bake limits only into the image.
